Agent Team

A personal team of four Claude agents that lives in Slack and Telegram. Message a teammate by name or post in a project channel; they work in the background, pass work to each other, run daily routines, and ask before sending an email or booking a meeting.

  • Node.js 22
  • Claude Agent SDK
  • Anthropic API
  • Slack Bolt · Socket Mode
  • grammY · Telegram
  • Gmail + Google Calendar API
  • Microsoft Graph
  • AWS EC2 · systemd
  • node:test · GitHub Actions

How a message moves

  1. 1Event. A Slack message (Socket Mode) or Telegram update (long polling) reaches its adapter. Anyone but the owner is ignored.
  2. 2Route. Names at the start ("Kai and Nova, …") or @mentions pick the teammates; otherwise the conversation's current teammate; otherwise Claude Haiku picks from the channel's team.
  3. 3Queue. One job per teammate, with the channel's context. Jobs in the same conversation run in order.
  4. 4Run. The Agent SDK runs the teammate with only its own tools, resuming its session and showing it what teammates just said.
  5. 5Reply. "on it…" appears at once under the teammate's name, then is edited into the answer.

Working as a team

  • Hand-offs. ask_teammate queues a job for another agent with the full context. Remy drafts, Iris sends; Nova researches, Remy writes it up. Capped at 3 hops.
  • Shared context. Each conversation keeps a short log of who said what, so the second teammate builds on the first instead of repeating it.
  • Routines. Every morning Remy writes an X post silently, hands it to Iris, and Iris DMs it for proofreading. New routines are proposed by the agents and start only after approval.
  • Approvals. Emails, calendar events and routines wait for ✅ / ❌ buttons, run exactly once, and expire after 48 h.

Design decisions

  • No inbound ports. Both chat apps connect outward, so the server only exposes SSH from one IP.
  • Least privilege. Each agent has an explicit tool list in dontAsk mode. Iris treats email as untrusted and can only attach files from workspace/.
  • Platform-agnostic core. Routing, teamwork, routines and approvals don't know which chat app they run in; adding Telegram meant writing one adapter.
  • Cost controls. Haiku where it's enough, per-task caps, a daily budget and costs on every reply.
  • Tested. 28 tests, including end-to-end runs against a fake Telegram API with the SDK mocked, in CI on every push.
